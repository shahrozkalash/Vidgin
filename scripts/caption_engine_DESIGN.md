# Vidgin Caption Engine — Round 3 design

## Scope and dependencies

A single Python 3.11 program processes `.npy` RGB clips and matching MiDaS inverse-depth arrays, or MP4 when optional OpenCV is installed. Required packages: `numpy`, `requests`. Ollama and an OpenAI-compatible **loopback-only** local server are supported. No cloud service, key, download, transcription or training code. The local model must already be installed. Stub is for testing only.

## Architecture and integrity

Discover manifests recursively; read original JSONL rows as bytes. Protected `caption_source=gemini` rows and failed rows are preserved byte-for-byte. Only successful VLM rows are serialized. Keep `caption_weak` a string and untouched. Hash RGB plus depth using SHA-256; skip unchanged VLM rows. Atomic temp + fsync + rename writes with `.bak`; per-manifest `.caption_progress.json` is atomic. Shards use SHA-256 of basename modulo N, 1-based. Existing Gemini rows are protected without `--force`; a backup enables byte comparison in `--verify`. Without a backup, identity with the prior state cannot be proven.

## Measurements

Uniform + frame-difference-peak sampling; optical flow uses Farneback if available, phase-correlation fallback otherwise. Pan and tilt labels are camera-centric, opposite apparent image translation. Zoom uses feature spread; not a calibrated 3-D camera estimate. Residual motion defines subject mask, center fallback when negligible. MiDaS larger depth means nearer; compare subject mask with outside, using relative depth contrast >0.2 near and <-0.2 far. Lighting: low_light if mean luminance <45 or dark share >0.75; high_contrast if standard deviation >75; bright if mean >=180; dim if mean <95; else even. Scene-cut threshold: peak frame difference >65 and >3x median; near-static median difference <2.5; near-black dark share >0.8. Camera and lighting are code-owned, not model-owned.

## Observation-grounded generation

The model must return `observations` (frame-positioned visible facts), `subject`, `action`, `setting`, `start_state`, `end_state`. Two clearly marked invented few-shot examples anchor its output. Code constructs scene change and captions. Content words from subject and setting must occur in observations or measured facts; missing terms appear in `vidgin_grounding_flags` and force review. This lexical validator cannot establish true visual grounding: a model can hallucinate both an observation and its subject. No unobserved filler is added to reach 40 words; short captions are retained and flagged. Overlong scene-change text is shortened first.

Self-check generates a second candidate from alternate frames. Score = 3 if no grounding flags + 2 if 40–90 words + fraction of observations with content-token overlap in the caption - 2 per grounding flag. Higher score wins; ties select A. A margin <0.5 triggers review. These scores are deterministic heuristics, not evidence of truth. Synonym normalization map is embedded as JSON; `--suggest-normalizations` only prints proposals for human curation.

## Image pipeline and performance

`--frame-scale` defaults to 2 for HTTP backends and 1 for stub; OpenCV cubic resampling or NumPy bilinear fallback. Frame dedup compares mean absolute RGB difference against 1.5 and keeps at least four distinct **indices** (not necessarily four visually distinct frames). Per-clip cache keys `(frame index, scale, format)` and avoids repeat encoding across passes. Default PNG has a pure-Python implementation. `--image-format jpeg` uses optional OpenCV; with NumPy-only installation, PNG remains fully functional. JPEG reduces payload but may add encoding time. Cache and dedup reduce redundant processing; they do not guarantee model inference time. One clip is loaded at a time. Real T4 median <=10 s/clip including expansion/self-check remains **unmeasured**.

## Quality gates and honest readiness

`--eval-suite GENERATED_DIR REFERENCE_DIR` runs verify, joins separate manifest trees by relative chunk folder + clip basename, prints benchmark metrics, per-reference-chunk F1/length breakdown, writes 10-pair seeded human review pack, and prints READY/NOT READY with each gate. Required: zero verify violations; >=30 paired clips; >=95% 40–90-word compliance; >=0.50 mean synonym-aware caption token F1; <=10.0 median total seconds/clip with timing present; and no known stub provenance. The review pack requires human inspection; automated READY is **not** a substitute for a favorable human judgment. Without real Gemini reference manifests or model outputs, readiness cannot be claimed. Benchmark exact and synonym-aware field metrics are reported, not used as separate numeric gates.

## Limitations

Observation grounding is lexical, not independent visual fact checking. Optical-flow camera/subject separation, zoom, and depth masks can fail on textureless, occluded, cut-heavy or complex clips. Phase-correlation fallback cannot reproduce dense Farneback flow. Frame upscaling cannot recover missing visual detail. JPEG needs optional OpenCV. The verification backup is the latest pre-write snapshot, not an immutable original. The progress file is written at every incremental checkpoint and at manifest completion (not after every row by default). Human assessment and actual T4 throughput are pending.

## Round 4: skeptic, confidence, composition, human preference and workers

`--skeptic` sends only the draft caption and the sampled images to a separate adversarial verification prompt (same local model unless `--skeptic-model` is supplied). It requests claim-level `SUPPORTED`, `UNSUPPORTED` or `CONTRADICTED` with frame positions. A failing claim triggers exactly one banned-claim rewrite and one repeat check; remaining failures are preserved in `vidgin_skeptic_flags` and force review. The skeptic may share the generating model's blind spots; agreement is not proof of visual truth. The rewrite may change the caption's content and is subject to the same lexical checks.

`vidgin_measurement_confidence` holds heuristic scores in [0,1], **not calibrated probabilities**. Motion confidence uses grayscale spatial texture standard deviation (score `clip((median_std-5)/30,0,1)`) and frame-difference variation (factor 0.8 when its standard deviation is <20, otherwise 0.6). Zoom confidence is motion confidence times 0.85 for detected zoom, otherwise 0.5. Depth confidence uses inverse-depth p90-p10 contrast divided by absolute median depth. Thresholds: motion 0.35, zoom 0.45, depth 0.30. Below threshold: camera motion becomes `unknown` (or zoom is rejected); depth distance becomes `unknown` and placement `undetermined`. Depth mask coverage and flow-pair consensus are **not yet used** in these scores; noisy textured footage can still be overconfident. Measurements must not be mistaken for independent scene truth.

Composition supports optional `secondary_subjects` and `mid_state`. A distinct mid-state produces three temporal beats; otherwise the prior two-beat form remains. The fixed subject → action → setting → change ordering, no-padding rule, and 40–90-word target remain. Vague words `various, some, stuff, things, nice, beautiful, amazing, interesting, several` produce `vidgin_lint_flags` and a review flag, without automatic rewriting.

`--ab-pack N --ab-reference REFERENCE_DIR GENERATED_DIR` writes `vidgin_ab_pack.md` and a separate `vidgin_ab_key.json` with seed 42. It can also accompany `--benchmark` or `--eval-suite`. The pack contains randomized A/B captions and identical 1–5 rating and grounding-error prompts, without source labels. `--ab-score KEY RATED_PACK` counts tool wins/ties/losses from filled numeric ratings; unrated pairs are omitted. The A/B result is not an automated readiness gate. `--eval-suite ... --ab-result FILE` prints supplied human rating results, otherwise `A/B: not yet rated`. **Unrated automated READY is not evidence of superiority to Gemini.**

`--jobs N` uses a process pool, one manifest per worker; each worker creates its own backend HTTP session and atomic per-manifest progress file, with worker PID recorded. Shard filtering occurs within each manifest before captioning. Aggregate counts and timing medians are printed by the parent. Multiple jobs can overload one T4, so `--jobs 1` remains the default. Ctrl-C handling is best effort: a worker may finish its current manifest; process-pool cancellation is not a hard immediate kill.

### Remaining limitations

The skeptic is another model judgment, not independent ground truth. Confidence heuristics are not calibrated and do not yet include subject-mask coverage or flow-vector agreement; zoom and camera/subject separation remain approximate. The existing benchmark gates are unchanged (>=30 pairs, >=95% length, >=0.50 synonym F1, <=10 s/clip median, clean contract, real backend). The A/B rating is a human-only supplement. T4 runtime, real Gemini preference, and production-scale parallel efficiency remain unmeasured. This section supersedes the earlier statement that the system has only lexical grounding: optional skeptic checking is now available, but is not a guarantee.

## Round 5 — audit and operations

- **Provenance:** every newly generated VLM row stores `vidgin_backend` (`stub`, `ollama`, `compatible`) and `vidgin_model`. `--eval-suite` requires both a recognized non-stub backend and a nonempty model for **every paired generated row**. Older rows without provenance fail this gate, even if their captions look convincing. A reused registry result retains the original producer's provenance.
- **Immutable baseline:** `--snapshot-baseline DIR` exclusively creates `.gemini_baseline.json` containing SHA-256 digests of raw Gemini row bytes, keyed by relative manifest path and zero-based row index. It refuses replacement. `--verify` uses it preferentially, including detecting missing rows and changed source types; without it, `.bak` is explicitly a weaker fallback. Store the baseline in a protected backup for stronger tamper resistance; local files are not cryptographically authenticated.
- **Text-only Gemini references:** per-field exact and token F1 exclude reference rows with missing or blank structured fields and report applicable denominators; zero applicable rows display em dashes. Caption-level F1 is still computed. These field metrics are descriptive and not readiness gates.
- **Registry:** `--registry FILE` reads an append-only JSONL mapping canonical RGB+depth SHA-256 hashes to reusable VLM result fields. The last malformed line is tolerated. Entries come only from successfully generated tool rows; protected Gemini rows never enter the registry. Registry results are applied without changing unrelated row metadata. The file is flushed and fsynced per manifest. To prevent simultaneous writers, `--registry` currently requires `--jobs 1`; sharded workers must use separate registries and merge only after validation. Existing output rows can be skipped by hash before registry lookup.
- **Circuit breaker:** `--breaker N` defaults to five consecutive clip-level backend-category failures (`timeout`, `http`, `bad_json`), and `--breaker 0` disables it. A successful caption or registry reuse resets the count; non-backend failures reset it. A trip leaves all subsequent rows in that manifest untouched, emits the breaker summary, and exits nonzero in sequential runs. With `--jobs > 1`, counters are per worker/manifest, not a synchronized global breaker; independent workers can continue.
- **Preflight:** `--engine-check` checks `/api/tags` for Ollama or `/models` for a loopback-compatible endpoint, confirms exact requested model ID, and runs a synthetic clip through the actual pipeline in a temporary directory. It reports load/hash, analysis, model times, word count and grounding flags, with `ENGINE CHECK: OK` or a specific failure. Stub mode tests the pipeline but cannot prove GPU/model readiness. No existing manifest is written.

### Round 5 limitations

The Gemini baseline depends on stable row indices and relative manifest paths; deliberate reordering requires an explicitly planned new baseline, not automatic replacement. Registry append and manifest write are separate durable operations, so an interrupted run can leave a valid reusable registry entry for a manifest not yet committed. Registry storage grows without compaction. Breaker counting is per manifest and `robust_describe` may perform multiple HTTP attempts per clip. The model list check is exact-name matching, and preflight does not establish actual caption quality or T4 throughput. Existing limitations on optical-flow ambiguity, depth uncertainty, shared-model skeptic blind spots, and human A/B review still apply. The readiness thresholds remain unchanged: 30 pairs, 95% caption-length compliance, 0.50 synonym caption F1, and median total time no more than 10 seconds, plus conservative provenance.


## Round 6 — crash checkpoints and real HTTP recovery tests

`--flush-every N` defaults to **10 successfully captioned or registry-reused clips**; `0` preserves end-only writes. At a checkpoint, the engine atomically writes a complete JSONL manifest consisting of all processed prefix rows and the exact original bytes for every unvisited row, then atomically updates `.caption_progress.json`. The checkpoint uses a temporary file, file fsync, and `os.replace`; the manifest's `.bak` is created **only on the first write of a given run** and retains the original pre-run manifest through later checkpoints. After a crash and a new invocation, that new invocation has its own pre-run backup. The immutable `.gemini_baseline.json` is the long-lived identity proof. A hash-matching checkpointed VLM row is skipped on resume. The maximum loss in the idealized single-writer kill scenario is `N-1` successful clips since the last checkpoint; process or filesystem failures can also affect the currently executing clip. Checkpoint and progress writes are individually atomic but are **not one atomic transaction**: if killed between them, progress may lag the manifest. The manifest is the authoritative recovery record.

The append-only registry is flushed at checkpoints; it still requires `--jobs 1`. Each worker owns one manifest and its progress file. For `--jobs > 1`, checkpoints do not introduce concurrent writers to a manifest.

`httprecovery` uses a request-aware ephemeral loopback server to test both native HTTP backends against three scenarios: malformed first JSON followed by a repair re-ask; an ungrounded first candidate defeated by a grounded alternate; and skeptic UNSUPPORTED verdicts causing exactly one rewrite and a persistent review flag. The server routes behavior using request content, not request sequence. This validates serialization and recovery control flow, **not** visual accuracy or GPU latency.

### Updated limitations

A power failure can still lose up to the current checkpoint interval of work, and atomic rename does not guarantee directory-entry durability without a directory fsync. Progress counters describe work in the current invocation, not lifetime corpus totals. SIGKILL recovery is tested with a synthetic stub and local filesystem, not a real T4 session. No real model, human A/B, or production throughput quality claim follows from these tests. `--image-format jpeg` still requires optional OpenCV, and the compatible backend now labels encoded JPEG frames `image/jpeg` and PNG frames `image/png`. The baseline and per-manifest backup serve different purposes and must not be conflated.
